# Project guidance

- Preserve upstream attribution and keep Thunderden-specific changes focused.
- Keep the Thunderden release image unchanged. Do not add guest helpers,
  replacement applications, kernel modules or extra initramfs files.
- This is a demo. Tests must use only public fixtures, never real wallet material.
- Keep public code, documentation, tests and commit messages product-focused and
  generic. Do not include private conversations, personal access arrangements,
  account/device/network identifiers, workstation paths or personal diagnostics.
  Keep user-specific troubleshooting in the conversation unless publication is
  explicitly requested. Inspect staged changes for this before committing.
- Describe checks actually performed; do not present untested platforms or
  security properties as verified.
